# 功能验证矩阵

浏览器测试使用 Playwright Chromium，每条用例创建独立浏览器上下文，直接打开仓库的 `index.html`。测试数据只存在于临时上下文，不读取或修改用户浏览器和桌面版的数据目录。日期测试固定时钟为 2026-09-29 12:00（Asia/Shanghai），避免跨日、时区和月份产生随机失败。

```sh
npm ci
npx playwright install chromium
npm run verify
```

Linux CI 安装浏览器及系统依赖：`npx playwright install --with-deps chromium`。单独运行界面回归：`npm run test:browser`。失败时保留截图和 trace；用 `npx playwright show-trace <trace.zip>` 查看。多个测试进程不要同时写默认输出目录；需要并行启动完整 runner 时，分别指定 `--output`。

CI 在安装依赖后检查已知高危及严重依赖漏洞；失败时将 `test-results/` 中的截图和 trace 上传为 `browser-test-failures`，保留 7 天。

升级必须继承全部已保存数据，约束见 [AGENTS.md](../AGENTS.md)。`npm run check` 固定数据目录所依赖的应用身份并阻止启用安装器数据删除；`upgrade-preservation.spec.cjs` 使用隔离的持久浏览器目录验证关闭、更换程序文件和重启后的旧格式任务、课表、草稿、设置及布局。测试使用合成旧数据，不读取真实用户目录，也不替代完整安装器升级验收。

默认旧端为最小存储写入页面；设置 `TASKBOARD_UPGRADE_FROM` 为旧版 `index.html` 的绝对路径可加载实际旧页面。本机另以 `v1.1.4` 标签的页面验证通过：10 个产品存储键及 1 个未知键在更换页面并重启后保持原始字符串，历史查询和后续编辑保留原记录及扩展字段。设置选择固定日期，布局选择屏幕内浮动位置，以区分数据继承与正常的自动校时/边界调整。

桌面逻辑回归覆盖 Windows 原生点击区域、模态弹窗与拖动捕获、渲染崩溃后的输入释放与显式恢复、显示桌面后的层级恢复、最小化恢复、主动隐藏与独立置顶，以及 macOS 的轮询降级。模拟的桌面状态切换验证逻辑，不等同于物理 Win+D 验收。

新增用例覆盖桌面和面板之间切换时保持临时层级、普通应用前景时撤销提升、短暂空前景期间保持状态，以及原生隐藏恢复。保留主动隐藏、禁用课表、崩溃保护、用户 Pin 和模态临时置顶；显式显示及兄弟面板提升后检查模态窗口顺序。原生回调测试覆盖事件过滤、订阅失败降级、重入合并和停止监听。旧方案中已不再使用的窗口链遍历诊断已移除。

2026-09-30 本机 Windows / Electron 44.4.5 现场采集确认：点击桌面后，原安装版的面板仍可见、未最小化、未被 DWM 隐藏，但桌面位于其上方，原有 `moveTop()` 无法恢复。早期同步置顶再取消的方法能够恢复窗口，但用户仍看见闪动；将恢复改为系统事件触发也未消除闪动，因此当前版本已替换这两种方案。

当前方案在桌面或本应用面板为前景时持续保持临时层级，切回普通应用时解除提升并排到该应用之后，用户 Pin 状态独立管理。隔离双窗口实验记录了 32 次面板与桌面之间的切换，其中 31 次不需要设置层级；13 次切回其他应用时，两个面板均撤销临时置顶且位于前景应用之后。用户实际观察后确认本轮效果可用。实验也记录到窗口原生提升失效及后续两次被桌面遮挡的采样，因此进一步加入原生标志读回和直接修复，避免 Electron 缓存的置顶状态与系统实际状态不一致。该修复已通过真实原生降层故障注入验证；不将隔离实验视作所有显示桌面快捷键的验收。

## Electron 实机回归

在有桌面会话的 Windows 环境运行 `npm run test:electron`。脚本创建临时独立数据目录，验证真实 preload/IPC、任务与课表同步、主题语言字号同步、原生窗口独立置顶、隐藏后重载与恢复，以及课程校验提示可见性。退出后清理临时数据；不会写系统自启动设置。此回归已在 Windows / Electron 44.4.5 运行通过。

测试入口在加载产品代码前移除 Playwright 自动注入的三个关闭后台节流的开关，并断言开关不存在，使窗口遮挡与后台行为更接近正常启动。原生区域和 DOM 几何断言仍不能代替对最终屏幕像素的观察。

Windows 两个面板以 `toolbar` 类型创建，原生回归在初始化、输入、Pin、显隐和重载等阶段读取 `GWL_EXSTYLE` 并断言保留 `WS_EX_TOOLWINDOW`。macOS/Linux 保持默认类型，背景节流保持默认。工具窗口不会被 Chromium 当作不透明遮挡者，普通应用对面板的遮挡策略仍生效。

原生降层故障注入前核验 Windows 实际前景属于隔离面板，不能只依赖 Electron 缓存的 `isFocused()`。临时普通窗口先严格核验 `GetForegroundWindow` 与其句柄一致，关闭前再把前台交回测试面板。系统拒绝测试进程取得焦点时，可在 15 秒等待期间激活标题为 `Taskboard smoke foreground app` 的隔离窗口；不会放宽前景或层级断言。

课表拖动回归执行解锁、拖动、释放、切回主体并点击设置的完整顺序；同时核验指针捕获释放，以及 Windows 两个窗口的 `WS_EX_TRANSPARENT` 标志均已清除，防止仅检查 DOM 点击而漏掉原生点击穿透。

锁定吸附课表的回归拖动主体，使用真实 `GetWindowRgn` 检查拖动期间两个窗口均解除旧裁切，释放后恢复裁切且覆盖课表内部采样点；同时检查位置跟随及松手后高度不变。隔离实机采集曾发现旧版本课表从 400 像素缩到 220 像素，已将隐藏镜像的自动布局保存移除；显式恢复默认仍同步给真实课表。测试使用临时数据，不修改用户课程。

2026-10-01 进一步复现自定义短课表的内部裁切：锁定状态下滚动区仍为 340 像素，超出卡片底部，滚动到底也无法操作最后课程。`schedule-scroll.spec.cjs` 验证修复后的实际可点击范围；旧代码在 566×269 的课表中会有约 130 像素溢出。另用正常启动的隔离 Electron 窗口做拖动与屏幕观察，未复现默认高度课表的外框缺块，不能据此宣称所有原生绘制裁切均已排除。

2026-10-02 按左侧吸附反馈继续检查：新增用例在旧代码上确认课表会随主体越出视口，修复后组合在可容纳的轴上保持完整。原生区域检查不能只使用 `PtInRegion`：区域本身可以超出窗口，仍需检查课表矩形位于实际视口内。该轮真实鼠标拖动中捕获保持到松手；CDP 合成拖动曾提前丢失捕获，但当时未确定原因，不将其单独认定为用户问题的根因。

Windows 的 `setIgnoreMouseEvents` 会切换透明窗口样式，恢复启用后补一次 `webContents.invalidate()`；单元回归检查跟随面板恢复时重绘、连续位置报告不重复重绘，以及隐藏或崩溃面板不重绘。该补偿与屏幕边界修复分别验证，不将其视为已复现并排除了所有屏幕中间缺块。

2026-10-03 将验证扩展为真实浮动拖拽吸附，而非只加载预设吸附状态。旧代码可将原本在屏幕内的 566 像素宽课表吸附到 left=-39，锁定后仍持续越界；现在拒绝无法完整容纳的吸附目标。另确认吸附动画中可见位置与区域上报存在约 20 像素差异，桌面版同时关闭 CSS 插值和 FLIP 位移动画。连续拖动也复现了标题文字被选中、后续原生 `dragstart` 导致 `pointercancel` 的独立问题，现通过标题栏禁止选字及阻止默认指针行为修复。上述明确复现的问题不能替代用户对屏幕中间持续缺块的最终验收。

同日进一步在正常启动的 dev.5 安装版用真实鼠标复现：上方吸附的课表随主体右移 100、上移 20 像素后，屏幕画面仍停留在旧位置，被新位置区域切掉；而带调试连接的隔离窗口未复现同一现象。不能用后者的 DOM/区域通过代替普通启动验收。Chromium 152 的 [IsWindowVisibleAndFullyOpaque](https://github.com/chromium/chromium/blob/152.0.7977.130/ui/gfx/win/hwnd_util.cc#L117) 对简单矩形区域仍使用完整 HWND 矩形，但明确排除 `WS_EX_TOOLWINDOW`；[Electron 44.4.5](https://github.com/electron/electron/blob/v44.4.5/shell/browser/native_window_views.cc#L381) 的 `toolbar` 类型设置该标志。dev.6 采用这一窄范围修复，不添加全局禁用遮挡或后台节流的开关。用户随后在正常运行版本确认此次裁切修复可用，并授权发布 1.1.3；这不等于穷举了全部屏幕、系统与操作组合。

Windows 实机回归还检查真实系统事件的订阅与注销、普通应用覆盖未 Pin 面板的实际窗口顺序，以及注入原生降层后恢复临时置顶。测试分别检查逻辑 Pin 和原生层级：停留桌面时未 Pin 面板可以暂时带有置顶标志，切回普通应用后必须撤销；真实用户 Pin 保持独立置顶。

运行 `npm run pack:win` 生成运行目录后，可将 `TASKBOARD_SMOKE_APP` 环境变量设为 `dist/win-unpacked/resources/app.asar` 再运行同一脚本，验证打包后的应用代码与原生模块加载；测试仍使用开发版 Electron 和临时数据目录，不制作或运行安装包。

## Windows 安装器回归

构建 Windows 安装包后运行 `npm run test:installer`（也可通过 `MAKENSIS` 指定 NSIS 编译器）。脚本编译并执行安装器实际使用的自启动宏，24 项原生注册表断言覆盖无空格、空格和中文路径的命令引用、启用、取消勾选、旧禁用记录清理、重复移除和其他启动项保留。所有写入仅在随机 UUID 的非启动注册表子树中进行，结束后清理；不运行正式安装包，不修改用户真实启动项。Windows 发布构建会执行此检查。

完成页的两个选项默认勾选，点击「完成」后先应用自启动选择，再按需启动程序。交互安装、跨账户 UAC、实际登录启动，以及升级和卸载全流程仍需人工验收。正常从当前账户双击安装时，UAC 回调会将启动项写入该账户；直接以另一账户运行安装器时，自启动属于运行安装器的账户。

## 自动化边界

2026-10-05 工程自审的问题、修复证据、评分方法与复审结果见 [ENGINEERING_AUDIT.md](../ENGINEERING_AUDIT.md)。新增回归关注存储读取被拒绝时不覆盖旧数据、旧格式图片的来源限制、空日期周期、跨日截止日期、四向吸附组合缩放，以及 macOS 首次点击和模态层级。macOS 的构造选项和层级策略使用平台模拟验证，仍需实机验收。

- `task-menu.spec.cjs` 覆盖任务右键菜单、组内置顶与取消置顶、跨窗口同步、删除撤销和存储失败重试。Electron 实机回归另核验菜单打开时的原生输入区域、兄弟窗口 Pin 状态及撤销按钮的实际区域。
- `task-carryover.spec.cjs` 覆盖主线和每日支线的跨天继承、原到期日提示、完成后停止继承、旧记录兼容、日期范围、未来与周期筛选、多窗口同步、存储失败重试及应用时区/手动时钟。继承使用原记录，历史查询显示其当前完成状态。
- 当前产品没有任务标题编辑、文本搜索、数据备份恢复、课表导入导出入口，因此不声称这些功能已测试或已实现。
- 浏览器真实 Document Picture-in-Picture 权限、系统剪贴板图片、物理托盘点击、实际登录自启动、安装 / 卸载和系统缩放仍需人工验证。macOS 原生行为未在这台 Windows 机器上验收；桌面面板当前限制在主显示器范围内。
- 六种主题切换和资源路径有行为检查；不替代逐像素视觉评审。仅测试 Chromium，未宣称 Firefox / Safari 兼容性。
- UI 测试验证主要交互和已发现问题的回归，不穷举所有数据组合与操作顺序。
- Windows 已检查真实 Electron 最小化后恢复时不抢焦点、不改变用户 Pin；Computer Use 的坐标点击检查了两个面板之间的按钮操作，但工具会预激活目标窗口。Windows 键快捷键不在该工具的允许操作范围内，因此物理首次点击和 Win+D 仍需用户实机复核。
